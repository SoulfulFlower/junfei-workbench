# 持久图片任务

默认工作台 `http://127.0.0.1:18769`。复用当前目标已登录的 Ego TaskSpace 与 Page；脚本不会创建、接管或结束其他工作区，也不会读取密码或模型 API Key。CLI执行完由当前代理依 ego-browser 规则结束浏览器工作。

先在本地写 JSON。每个 `source`、`maskFile` 均为真实图片的绝对路径。`productId` 必须属于当前账号。输出目录首次绑定输入；修改输入时使用新的版本目录。不同 jobs 串行提交，逐项保存真实回执。

```json
{
  "jobs": [
    {
      "productId": "实际商品ID",
      "mode": "suite",
      "source": "C:/商品图/原图.png",
      "brief": "实际画面要求及必须保留的细节",
      "count": 6,
      "noText": true,
      "preserveSourcePixels": false,
      "neutralBackground": true
    }
  ]
}
```

`suite`：1–8张自由套图；可提供 `layoutTemplateIds`（从真实240项库选择的1–8个不重复字符串 ID）。不传则由后端按品类绑定已核验原模板。原片锁定模式适用于已识别服装；不生成新的商品姿态、隐藏结构或角度。该模式可用 `neutralBackground=true` 中和生成背景的色偏，在合成原片之前执行，不改商品颜色。正式图库仍按自己的张数、尺码和验收合同处理。

服装按图种制作时，改用`apparelSuite={"counts":{"white":1,"ins":1,"seller":2},"pointTemplateIds":["2095034511073947649","2095034508871938050"]}`，总count=4。不要同时传顶层layoutTemplateIds。每个选择的官方ID对应一张seller；ins、model、white和size不分配这些广告模板。未选pointTemplateIds时，由工作台从已核验库分配卖点版式；LinkFox私有随机策略未知，不声称复现它的随机种子。顶层layoutTemplateIds保留为我们的自由模板创作扩展，显式选1张且不指定图种时不再被默认白底图吞掉。

本地请求保留pointStyles来源元数据{id,style,imageUrl,materialSource:2,tabType:"1"}，以原ID与Hash绑定资产。原生LinkFox前端仅提交这组选择元数据，其私有最终模型提示词/图像权重仍未知；工作台把真实配图与完整公开模板原文送入自己的Codex，是独立适配，不发送LinkFox的加密传输包装、登录或算力请求。A+在原生是独立aPlusStyles选择，不混为服装seller或正式七图。

默认模板生成不要启用原片锁定。`noText`按用户要求选择；需要模板图文层次且未要求无文字时使用false，文案仅写有事实依据的短句。新任务保存`templateExecutionPolicy=official-artwork-v1`；逐图`templateExecution`记录实际配图和完整原提示词是否进入模型，独立复核同时比较原模板并返回`templateFollowed`。只保存ID/哈希、仅放大原图或仅换背景不代表执行了模板。展示模板测试时把实际原配图与成图并排，不把原片合成结果称为完整模板生图效果。

原策划已完整返回、仅因工具支持的结构化字段格式失败且尚未提交任何图片时，可用`reusePlanTaskId`派生接续。后端核实同账号、商品、原brief、参考图SHA、模板及参考角色完全一致，冻结原策划与原错误；不再次调用策划模型。未知提交、有图片意图/任务号、已有成图或输入改变都不能复用这个入口。

模板原生成图已返回、后续仅因单图校色器不能处理多分区衣料边界而失败时，`reuseGeneratedTaskId`核对原提供方completed状态、原生文件SHA、原提示词与完整参考顺序，再接续原生输出和未生成图位。已检查成图保留，未检查输出仍须完整颜色/结构/模板复核；未知或不匹配任务不能使用。冲突蒙版不用于自动改色，原生输出不因保留原像素就获得质量通过。此处不更改独立换色功能的选区、发丝、保护区或成图门禁。

有真实背面或细节原图时，可提供`referenceFiles`（最多2个本地绝对路径），与`source`合计最多3张，保持原接口上限；按相同顺序填写`apparelSuite.referenceRoles`。脚本逐张冻结文件SHA并保存上传回执，不用异款特写或生成图充当原始结构真值。

服装可提供 `apparelSuite={"counts":{"white":1,"model":1,"seller":1}}`，数量之和必须等于count。多张模特图须提供实际 `consistency.modelReference`（工作台已上传图片URL）；场景精确一致还须真实sceneReference。后端冻结参考图用途和哈希，再按图位绑定原模板。当前Codex交付画布为1600方图；不能提交未经当前模型配置支持的任意比例。

`repair`：提供 `repairTemplateId`（24项原模板之一）；不选原模板时可用 `editTask=background|cleanup|relight|detail|free`。`needOptimize`默认false；明确true时，使用原始优化指令经当前Codex Tools文本路线扩写，再提交图片模型，保存扩写前后原文。原配置needOptimize、供应商选项作为来源元数据保留，不切换执行供应商。`repairObjects`可传text/tag/newLine节点，其实际文字必须与brief一致；括号示例不视为用户输入。`brief`必须说明要变动和保留的内容。

`colour`：优先提供真实同款目标照片的绝对路径 `targetReferenceFile`，工具自动识别目标衣料并取色；或提供已有实测依据的 `target=#RRGGBB`。不提供 `maskFile` 时，通过持久的 `/api/image-tools/start` 选区任务调用当前账号Codex视觉规划、联合SAM/原像素GrabCut、matting及独立复核，不由代理手工标点。可显式提供同尺寸 `maskFile`，但回执会记录人工选区，不能计为零人工验收。原件先归一为无损PNG，保留原件与哈希。浏览器执行全部11级原始 GLSL，再上传结果和源码哈希/参数回执。后端严格校验选区外原像素和 alpha，并绑定独立成图检查的真实输入哈希。`colourSettings` 可按原配置索引覆盖参数。默认不调用生成模型重画商品；显式 `polish=true` 追加 Codex 局部修整并单独保存/复核。

自动流程默认 `matchTargetSample=true`：后端从当前原片/蒙版实测衣料锚点，使用原始换色和曲线参数匹配目标中间调；深色保留光影后按曲线压低亮度，减少阴影截断。参数及独立校准回执完整保存，显式colourSettings优先。明确false保留原生页面参数。修图可明确preserveSourcePixels=true、neutralBackground=true：仅生成空背景，原片商品和搭配合成回来，保留原姿态；不声称商品已重新打光。

共享锚点时用 `colourSettings["4"]={"bSetMainColor":1,"clothingMainColor":[实际R,实际G,实际B]}`。这些值来自当前母版原图，不能继承其他SKU的样例值。原参数 `bAdjustLight` 会混合保留原亮度，深色目标可能因此偏浅；可通过原亮度滤镜 `"5":{"enable":1,"lightness":实际校准值}` 调整。相对HSV迁移出现灰色/杂色时，可据实际图片测试原 `bUseBlackFun`；它会先按源最大通道中和，再迁移目标饱和度。所有参数应保留于回执并对照真实目标图复核，不为通过检查改写旧结果。

```text
python <本Skill绝对路径>/scripts/workbench_images.py --job C:/任务/jobs.json --space 当前TaskSpace数字ID --page p1 --output C:/任务/结果-v1
```

输出目录包含 `workbench-jobs.json`（原图哈希、完整payload、requestId、taskId、状态和结果）、按任务号保存的PNG、下载SHA256及每次调用的独立执行文件。相同命令可续查和续下载。原图或蒙版哈希变化会停止；不能复用旧意图生成不同内容。查询超时保留任务，不启动第二次模型生成。

`matchTargetSample=true`现会先保存GPU初始预览，再实测预览衣料的中间调；偏差超过一个RGB通道步长且无已有自定义曲线时，最多补一次原生R/G/B曲线校准。初始图和反馈审计留存，不重复调用生图模型。该中间调校准不能替代边界检查：浅色袖片可能被人体模型误当手臂，细肩带也可能被当成衣服。使用两模型和原片证据核对，必要时以明确前背景点、GrabCut与软边matting修正并保存新蒙版；不把失败选区当成合格结果。

GPU渲染使用原生曲线算法、纹理上传和11级GLSL链；相同参数下，本机RTX4060上14组合成案例与两组1280商品图逐级零字节差异。交付显式启用选区外原像素恢复，回执分别记录原生结果与交付结果SHA；该保护模式有意区别于原生滤镜扩散。默认页面sigma=0，原config的sigma=.5仍作为来源保留。此证据不代表所有GPU、恒亮退化输入或私有服务端AI逐像素一致。自动选区使用衣物/人体语义及原片细边证据，须检查流苏、皮肤、靴子及空隙，不能仅依据接口完成认定通过。

工具版本更新后，`/api/image-tools/retry`仅允许服务端已明确记录的选区/本地失败派生新任务，保留父任务并使用确定的requestId；模型调用已开始却没有完整回执、interrupted和unknown均不得自动接续付费。不要通过换输出目录绕开未决任务。新旧算法版本、实际约束与独立检查都保留。

目标参考图取色由独立 `reference_sample` 任务选择并复核真实衣料中间调样区，保存真实像素、坐标与样区哈希。它只证明目标色样，不要求整件衣物覆盖；返回sampleVerified，eligibleAsSourceSelection=false。源图仍必须走完整selection与成图检查，不能把小块取色蒙版作为完整换色选区。

修复原片锁定的背景修图工具后，可在新版本目录用 `reusePlateTaskId` 引用已明确完成的同一原片、同一要求和同一原模板任务；后端只复用已核验最终空背景及完整扩写回执，避免重复生成背景。最终合成仍须重新检查，旧失败图不改写。正方形交付按自然比例放置原片，不把竖幅原片直接拉伸为方图。

选区自动纠正只提交服务端 `qualityCheckId` 和 `previousSelectionTask`；后端核对当前账号、商品、部件、原片/蒙版/成图真实SHA，再读取原质检。符合局部研究条件的漏选报告先经当前账号Codex Tools核实真实衣料、配件及准确位置，报告点不能直接作为衣料正点。明确缺陷才在原片256像素局部调用离线分割，区域外旧alpha逐像素保留。解剖、显式、已证背景及真实负点的硬保护不释放；模型宽路径需目标衣料与遮挡物双实例证据才能局部释放，证据不足就停止。新蒙版仍须原数字门禁、新独立源图复核和完整成图检查。既有合并工具另有局部增量范围守卫，不允许远处随全局重算增加选区。

自动规划可附带最多6处真实源像素的小衣料候选放大图和精确原图坐标。这些只是待核实假设，既不直接补蒙版，也不因同色就认定同款；仍由本轮规划选择真实衣料点，并执行原选区与成图门禁。不让代理为候选手工填写坐标；语义、颜色与来源证据不足的部位保留未通过事实。工具内部仅在前一轮数字通过、独立检查明确纯漏选时保留旧候选，当前保护优先，新蒙版重新检查；不增加模型轮数来刷通过。

局部核实若认为是已换色像素、非目标物或自然混合边缘，可形成 `auditOnly=true, maskChangedPixels=0` 的澄清，仍须新独立源图复核和一次带局部证据的完整成图检查；不会因“只是warning”直接放行。`uncertain`停止，不用新目录或循环重评刷通过。任务分别记录首次通过、实际像素纠正通过、仅证据澄清后通过及失败；下载和原回执全部保存。局部模型是本机固定revision/SHA的SAM2.1 CPU隔离环境，只提供候选，不取代当前账号Codex Tools的分析及复核。其他电脑缺模型或依赖时按安装合同补齐，不复制账号密钥或默默换供应商。

报告中同时含疑似泄漏时，先研究源像素归属，不把它改名为漏选补色。局部工具v3可处理明确的非目标弱alpha误选：Codex核实实际染色像素和应保留的衣料点，再由独立的衣料/非目标双实例分割共同确定删除范围；只删除有界、小面积且alpha低于230的连通区，原不透明衣料、真实衣料锚点及ROI外选区保持。候选仍须原数字门禁、新源图复核和当前完整换色检查。范围过大、实例冲突、不透明误选、缺字段或归属不明均停止，不回退重算整张选区。该边界限制是工具纠错范围，不降低任何成图验收条件。

局部工具v5为已经确认的发丝染色增加专用连续alpha处理：原图、实际染色点、双实例及独立人体发丝标签共同提供证据，衣料/发丝真实色样只建立trimap种子，再以原图RGB引导闭式matting求解。只处理与真实染色点相连且更符合发丝的区域，只降低选区alpha；原生衣料实例、原衣料锚点、更符合衣料的源像素和ROI外选区不变。被错误选为不透明的发丝也可降低选区透明度，这不等于允许删除不透明衣料。完整源图复核及成图检查仍必需，不能凭matting数值收敛或旧通过回执交付。保护物已被染色的原报告可授权这种有绑定的纠错研究，仍保留其原失败状态。

局部工具v6可自动覆盖质检点所属的同一独立发丝连通物体，补充的区域仍只是源图假设：最多6个256像素ROI，总范围不超过35%，逐区核实并保留原图坐标。强衣料证据与原生衣料实例保持不变，疑似混合像素由连续alpha决定，不按单点色差直接清零。覆盖仍在一次纠正中完成，随后一次新的完整检查；任一区域的归属、实例或范围冲突均停止。针织斗篷实测仍有发丝范围冲突的失败记录，不宣称此版本已实现任意发丝零返修。

局部工具v8可额外读取当前账号原QC绑定的真实目标参考图。`reference_pose_evidence.py`先核实同视角匹配、重投影误差、空间分布的非目标匹配、非目标稳定比例及真实衣料变色信号；失败则不启用这份证据，不能按相似文件名或同尺寸假定同一照片。参考RGB只参与分析，不复制到成图。已验证的同视角未变化像素仍是假设，每个局部须由Codex核实原图发丝/衣料、两次原生分割与独立人体发丝标签交叉佐证，并具有实际变色的真实衣料正点，才提出降低发丝选区alpha的候选。发丝自己的亮度不能当作其下方衣料亮度来推断颜色响应。

工具在付费核实前，从同一发丝物体自动规划不同的原尺寸上下文区域，并预估最大改动量；原区域数、256像素边长、35%联合范围、每区0.5%源像素/15%ROI修改预算和8像素边缘渐变均保留。所有风险候选须被区域内部覆盖，不能遗漏密集区域来通过；无法满足原预算就停止，不循环切片规避上限。每区独立核实后仍保留原生衣料实例、旧真实衣料锚点、硬保护和ROI外选区，新源图复核与完整换色检查全部必需。原始失败、工具升级恢复及从原图新跑的结果分别记录，不把已修复历史案例当作首次通过。

局部工具v9为这些自动候选提供源像素编号及独立显示图。存在同视角证据时，Codex只可在实际检查原片/旧alpha/旧成图后返回`evidenceWitnessId`；后端使用该编号的精确源像素，不使用模型另写或四舍五入漂移的坐标。候选按实际染色可见度和空间分布排序仍不代表归属已证实，没有可确认候选就停止。原图列不加标记，标记仅出现在单独的展示列，绝不写入商品原图或结果。

局部工具v10将同一发丝物体的混合边缘也纳入原预算的预检覆盖。严格未变发丝仍以原RGB差值≤3提供背景种子，原生衣料实例提供前景；闭式matting同时使用源图和配对参考的6维RGB特征求连续alpha，处理JPEG微差与物理混合边缘留下的灰点。没有提高未变像素容差，参考RGB仍不进入交付图；只降低有语义/双实例支持的同一源发丝选区，原生衣料及全部旧保护继续不变。算法收敛、数值通过或带提醒的旧通过都不是零缺陷证明，实际成图需放大对照原图并保留提醒。

原生SAM2后端v2采用模型一次输出的多种原生候选，先逐个检查全部前景/背景点，仅在满足所有原约束的候选中排序选用；没有候选满足就停止，绝不强制涂改点像素或放松负点约束。保存全部候选logits、分数、选中编号、原生选区与哈希，并检查交付候选确实来自该原始输出；预测分数只用于有效候选之间排序，不证明商品质量。权重与依赖固定版本不变。

原生后端v3同时保留原生单候选与多候选的3个结果，因为单候选token不包含在多候选中；全部4个结果仍按原完整点约束筛选，没有合法结果就停止。QA v6增加由当前原片绑定的手部保护对照，展示原图、实际alpha、输出及RGBA绝对差分；语义标签和零差异数字均不覆盖独立复核false旗标，原验收POLICY及一次纠正上限不变。确有新工具/证据策略时保留旧失败，再完整复核一次；没有新证据不得循环重评。同图证据澄清不得冒称重新生成或像素修正，须记录复核前后成图SHA。
