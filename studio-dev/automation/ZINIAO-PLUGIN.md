# 钧飞后台插件自动打开与身份核对

当前实现使用已安装钧飞扩展 manifest 中 `action.default_popup` 的实际页面，通过紫鸟 CLI 打开同一插件 UI。它不依赖桌面坐标、不进入扩展管理页、不另造登录接口，也不读取或迁移 Cookie、密码或令牌。

先按 ziniao-store 技能精确解析并打开授权的紫鸟店铺，再运行：

```powershell
python -X utf8 automation/ziniao_plugin.py --store-id <实际ID> --store-name <实际名称> --market US --seller <实际后台店名> --account <实际ERP账号名> --ensure-site --receipt <绝对回执路径>
```

`--ensure-site` 会先打开相应卖家后台，核对真实域名、店名和国家，再打开插件并等待登录状态，最后同时断言插件店名、站点及 ERP 用户。首次加载显示登录表单不算失败或成功；只在真实“用户…退出”状态出现后通过。无法确认登录或身份不符时停止，不提交商品。正常导航的文字回执和导航后 CLI 报错均不能替代页面回读；不会因报错重复导航或提交。

2026-11-17 增加显式授权选项 `--allow-market-dom-click`。同一店铺选中市场不符时，默认会通过实际账户菜单尝试唯一可信点击；只有用户已授权受控 DOM 后备时才添加该参数。`ziniao_market.py` 核对同店铺、唯一国家行、国家旗标、可见启用及无遮挡后优先使用紫鸟可信点击；可信输入明确遇到坐标 geometry 故障且有该参数才允许受控 DOM 点击。已展开菜单不再点标题，任一点击结果未知先读实际选中 header，不重复点击；最后仍须真实域名、选中店铺/国家及插件用户全部核验，菜单出现国家文字不算切站成功。脚本不访问私有应用状态、不读凭据，市场选择与登录等待共用原站点超时预算。

同一个紫鸟环境的后台插件会跟随当前已注册站点。美国、英国应串行操作，每次同步品牌、查询豁免、交接或发布之前重新执行当前站点核对，不能把另一站此前的“在线”当作本次可用。脚本本身不创建草稿、申请豁免或发布商品。

2026-11-11 在授权环境“示例店铺”已实际验证：美国/英国后台均为 Example Store，插件均显示账号“示例ERP账号”；完成无人工点击的切站、打开及回读。ERP 对应别名为“示例店铺-美国”“示例店铺-英国”。实际回执保存在本轮产品 artifacts 中，不将这些店铺参数当作以后批次的默认目标。

验证：`python -X utf8 -m unittest discover -s automation -p 'test_*.py'`。本轮 110 项通过，包含误导航回执、账号/店铺错配、异步加载及实际站点检查。
