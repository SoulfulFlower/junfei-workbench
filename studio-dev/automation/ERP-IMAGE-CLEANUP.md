# ERP 图片空间清理

图片空间不足时，先确认当前电脑已取得清理旧图授权；历史电脑的授权不随单机包迁移。

当原草稿任务报告图片空间容量超限，保留产品、任务号、图片哈希及外部回执，调用 erp_image_cleanup.py。它复用当前工作台账号的历史采集和刊登包，通过对应的 EGO 页面读取当前美英在线记录及图片空间。

脚本仅选择当前在线记录能唯一对应、全部子 SKU 有 ASIN、涉及的所有子 SKU 已有完整 Amazon 图库、原文件 SHA-256 一致、没有其他产品交付包引用的旧图。原始主图和附图适用相同条件。旧包内的 publishing 或 accepted 状态不作为清理依据，必须回读当前在线结果。证据不完整的图片保留。

在项目根目录调用，先将参数替换为当前实际数据目录、ERP 绑定及新输出目录。

    python automation/erp_image_cleanup.py --data listing-workbench/data --binding 实际ERP绑定 --required-mib 120 --output 当前清理目录 --execute

required-mib 按当前超额用量、本款待上传图片字节和适量余量计算。省略 --execute 仅生成清单。每次输出目录保留 request、当前在线回读、清理前后图库、原始文件哈希和删除日志。删除前核对页面选中的精确链接集合，由原生界面提交。脚本支持直接删除及确认框两种行为，捕获原生文件 ID、HTTP 状态及业务码。

删除请求前日志先记 delete_unknown。超时、断线或崩溃后不要重放整个操作。调用模块的 reconcilePendingDeletion 重新遍历图库核对原批次，只有原链接全数消失才记录已删除。已知未提交的请求则保留原图片并诊断。首次验收中有一批页面直接删除，日志以完整图库对账保存链接，其文件 ID 未捕获，记录 nativeIdsUnavailable，后续批次已在点击前安装回执捕获。

清理后检查实际剩余容量，并沿原草稿任务再次获取上传授权。张数下降、清理估算值和列表无原链接只能说明对应阶段的结果，不能代替容量恢复或本款草稿回读。空间恢复后从原任务继续，图库、SKU、文案均按原内容核对，当前只做草稿的任务继续止于草稿。
