# 本地有界循环：只读安全评估与离线控制模拟

## 当前边界

`discovery_run.py` **没有启动真实自动选品的接口**。它不调用浏览器、不导航、不采集、不入库、不调用付费服务、不上传图片、不发布商品。没有通用执行回调，也没有能连接真实执行器的 adapter 参数。

本次交付分两部分：

1. `inspect(user, data)`：读取当前账号的计划、全部采集历史及有效浏览器绑定，供 API/UI 展示未满足的条件。即使配置齐全，也始终返回 `executionAllowed=false`。
2. `OfflineSimulation`：用明确标记的合成数据，在独立临时 SQLite 中测试累计限额、并发预留、停止、取消与崩溃后的未知状态。它不是产品发现、来源核验或实页运行证据。

不能将模拟的 `simulated_observed` 解释成真实采集成功。所有状态响应标记 `mode=simulation_only`、`simulationOnly=true`、`liveExecutionEvidence=false`，真实外部调用、核验通过和入库计数均为 0。

## 只读接口

`inspect(user, data)` 的请求与 `discovery_plan.prepare` 相同，且只允许以下字段：

- `cycleId`：当前账号的循环 ID。
- `expectedRevision`：精确版本号。
- `maxActions`：1–20 的整数。
- `maxRounds`：1–20 的整数，含义是**允许的绝对拟议轮次编号上限**，不是“再跑多少轮”。

返回 `status=execution_disabled`、计划/图谱/采集历史指纹、绑定就绪状态与指纹、阻断原因。不会返回 CLI 路径、凭据或绑定配置。绑定已配置不代表真实浏览器所有权已核实，`binding.liveOwnershipVerified` 始终为 false。

接口先生成计划，读取绑定，再重新生成计划并核对指纹；绑定已配置时再次核对绑定指纹。版本、计划或配置变化会拒绝，而不是把旧计划当执行许可。此过程只是双重读取的保守快照，**不是跨数据库/浏览器的原子锁**。未来不能依靠此接口消除检查与执行之间的竞争。

未解决的任何账号采集记录仍由现有计划模块统一阻断。不能通过更换循环、采集种类或请求 ID 绕过未知结果。只读评估固定另报真实有界执行器未实现、真实导航及页面所有权未验证、模拟不构成真实执行证据等阻断项。

## 合成控制器

显式调用 `OfflineSimulation(existing_temp_directory, simulation_only=True)` 才会创建 `discovery-run-simulation.sqlite3`。目录必须是操作系统 TEMP 的既有子目录；不能使用 TEMP 根目录、工作台默认 data 目录或当前 `JUNFEI_ACCOUNT_DATA` 目录及其子目录。不会默认选择生产 DATA。数据库有独立模式/版本标记，不会接管其他 SQLite 表。

这只是防止误用的边界，不是抵抗任意本地代码或管理员篡改的安全沙箱。删除合成数据库当然会丢失模拟记录，不能靠它为生产重试提供依据。

`simulation_snapshot(...)` 只接受合成账号、循环、版本、图谱/历史/配置/所有权指纹和有限动作。动作字段只允许 `actionId`、`sourceEventId`、`kind`、`proposedRound`。不接受 URL、命令、产品资料或 callable。完整快照包含内容指纹，用来测试陈旧计划、图谱、配置及所有权变化的拒绝行为。这些指纹都是测试输入，不是实时所有权或实页证据。

主要操作：

- `create(...)`：持久化不可增加的 `max_actions`、`max_rounds`。相同账号/run ID/初始输入重复调用返回已有状态，改变输入或限额会报冲突，不重置预算。
- `reserve(...)`：在 `BEGIN IMMEDIATE` 事务内扫描账号全部未解决记录、挑选未尝试的动作、累计消耗一次额度并写入带租约的预留。先计额度，不因失败、停止或取消返还。账号/循环/action ID 有唯一约束，换 run ID 也不能重试该动作。
- `begin_simulated_dispatch(...)`：核对精确快照、租约和账号屏障，再持久化 `dispatch_unknown`。仅改变 SQLite 状态，**不执行外部动作**。
- `record_simulated_outcome(...)`：只接受固定合成结果。写入失败保留未知；配置/图谱/所有权/历史变化或派发后租约过期转为 `unknown`。unknown 不提供自动修复、清空或重试入口。
- `refresh_simulation(...)`：仅在无未解决动作且未终止时提供下一份合成前沿。要求图谱版本上升且图谱指纹变化，账号、循环、配置、所有权保持一致。**不重置累计额度**。
- `stop(..., cancel=False/True)`：预留但未派发可标记为取消前置动作；已经持久化派发意图的记录保留未知屏障。并发取消和派发由同一 SQLite 事务锁排序。取消后收到匹配的、未过期合成回执可以记录结果，但不会恢复运行。
- `status(...)`：只读、账号隔离，不暴露预留令牌，不延长租约，不因超时自动抢占。输出全部本 run 尝试及账号未解决屏障。

预留超时不会自动重试。明确尝试开始一个已过期但确定未派发的预留时，标记 `expired_before_dispatch` 并终止该 run；额度不退。派发后超时保留未知状态，不能自动认为失败。无新前沿时进入 `simulation_waiting_for_plan`，不虚构后续商品；达到动作或轮次上限时终止。

数据库采用 `synchronous=FULL` 和短事务。预算增加与预留写入同一事务。账号级屏障扫描全部记录，不采用 UI 最近 100 条的窗口。不同账号可以独立模拟；同一账号不同循环/不同 run 的未解决动作互相阻断。

## 离线验收

在 `listing-workbench` 目录使用：

    python -B -X utf8 -m unittest test_discovery_run -v

测试导入图谱模块前将导入目录指向 TEMP；每例另设临时图谱、采集或模拟库。模拟测试禁止 subprocess 和 socket 调用。覆盖：

- 整数及绝对轮次边界、预算跨重启和前沿刷新累计、相同 run 重复创建。
- 多线程同时预留只能一人成功；取消与派发竞争不会丢失未知屏障。
- 预留崩溃、派发后崩溃、租约过期、不重放未知结果。
- SQLite 中途失败的事务回滚、结果写入失败保留屏障。
- 跨账号隔离、跨循环屏障、陈旧快照、配置/所有权变化。
- 只读状态与评估不改库，不把已配置当浏览器实测。

离线通过不等于真实全自动选品通过，更不等于素材、利润、货源、SKU 或发布通过。

## 真正继续运行前仍需实现

1. 把真实动作意图和账号级互斥与现有采集 attempts 置于统一、可验证的协调边界。目前合成库不锁生产采集库。
2. 在同一受控任务空间核实账号、站点、页面身份与实时所有权；只提供明确白名单导航，不提供任意脚本执行。
3. 导航前、派发前与回执前重新核对图谱、计划、配置及绑定；取得真实回执，验证后再按新版本入图。
4. 真实环境中验证并发、崩溃、取消、超时和外部结果核对流程。未知派发必须核查，不得以换 run ID、目录或采集种类重试。
5. 将跨轮累计动作/轮次硬限制、停止请求和可审计回执接到真实执行器后，再逐项受控验收。现阶段不得增加“开始自动执行”按钮。
6. 商品同款/变体排重、数值排名、1688 货源与当前利润各自需要可追溯证据。随后图片、刊登及跨站发布仍按各自配置、授权与核验流程执行。

## 后续隔离试验实现
`discovery_live.py` 是独立的、显式启用的源码试验执行器，不改变上面的合成控制器。它仅允许 OS TEMP 内的隔离 DATA、临时项目配置、单账号 marker 和不被原工作台占用的新 EGO 空间；拒绝正式配置、员工运行时及便携程序。没有生产“开始自动执行”按钮。

生产就绪接口仍返回 execution_disabled，另以 isolatedPilotAvailable / isolatedPilotScope 标明该试验模块存在。这不代表正式工作台已可无人值守运行。详见 DISCOVERY-LIVE.md。
