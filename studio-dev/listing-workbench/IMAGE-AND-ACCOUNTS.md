# 产品图流程与团队登录（2026-10-26）

## 参考与实现范围

阅读了用户提供的 IvyeaOps README、`docs/listing-visual-studio.md`、`skills/amazon/amazon-listing-creative/SKILL.md`。参考项目标注 AGPL-3.0；本次独立实现工作流概念，没有复制其程序代码、运行可执行文件、读取其账号数据或导入其整套技能。其订阅 OAuth 登录与员工账号体系用途不同，未照搬。

主要借鉴：一张可信产品图锁定外观、统一整套视觉方向、每张图承担不同购买问题、按用途编译详细提示词。我们原来的问题包括：未保存方案时实际请求退回简短泛用提示词；多张参考图未区分主次；整套缺少共同风格和明确的产品外观约束。已修正这些环节。

当前不包含参考项目的自动视觉审核、OCR、自动修复、A+制作或整图文字排版。默认生成无字产品底图；尺寸与卖点图仍需核实事实并排版，不代表已达到可直接上架标准。尚未用真实付费生成结果做前后效果对比。

## 作图使用

1. 产品库 → 编辑产品 → 图片工作台。
2. 采集图/实拍图里，给一张清晰、同款同色的照片点“设为主体图”；最多再选三张同款同色细节图。主体图优先传给模型。
3. 填写“本次颜色 / 规格”，避免用其他颜色的参考图。
4. 在“产品视觉身份与整套风格”填写受众、场景、光线和色系，点“应用要求并更新7张方案”。此步骤保存要求并替换旧方案，不调用付费模型，也不改变已有生成图片。
5. 切换图片用途，检查和编辑该张详细要求；“保存当前图片要求”后再生成，或批量生成剩余用途。旧产品已有方案不会静默覆盖，请主动更新后测试。
6. 先生成一张验证外观，再批量生成。人工逐一核对颜色、比例、结构、口袋/拉链、材质、配件数量。提示词可以降低偏差，不能保证模型完全保真。

## 账号使用

刷新本机工作台，首次显示“创建首位管理员”。账号3–40位英文/数字/点/横线/下划线，密码12–128位；没有预设账号和密码。账号保存于 `data/accounts.sqlite3`，与产品库、模型密钥分开，重启保留。

员工点击“注册员工账号”，注册后暂不可登录；管理员在右上“账号与插件”审核通过或停用。员工共享同一个产品库和任务记录，没有个人数据隔离。模型密钥、测试、提示词全局保存和账号审核仅管理员可操作。员工仍可编辑产品和生成内容，使用团队配置的模型。

密码采用带随机盐的 PBKDF2-SHA256（600000次）散列。登录会话12小时，HttpOnly/SameSite Cookie；数据库仅存令牌散列。退出使当前会话失效，停用员工会撤销其全部会话和插件配对码。连续8次失败锁定该账号/IP组合15分钟。

## 采集插件升级

登录上线后，采集接口也要求授权，旧插件需在浏览器扩展管理页点击“重新加载”。本次扩展版本0.4.0。

工作台右上“账号与插件”→“生成 / 更换插件配对码”，复制到插件中的配对码输入框并保存。配对码只允许提交采集商品，不允许读取产品库、修改模型配置或查看密钥；30天过期，重新生成立即撤销旧码。插件将它存于当前浏览器扩展本地存储，不要分享给无关人员。

## 部署边界

当前仍只监听 `127.0.0.1:18765`，员工账号功能可用，但其他电脑尚不能连接。正式10人协作还需部署共享服务器、HTTPS、备份与恢复、并发编辑策略；本次没有开放公网端口。当前共享产品库继续采用版本冲突提示，遇到冲突需刷新后重新编辑。

本地维护人员应备份整个 `data` 目录；管理员密码遗失的自助找回暂未实现。

## 检查

运行 `python -m unittest discover -q` 检查账号、权限、采集、图片接口与已有功能。浏览器UI检查使用隔离数据库，不创建真实管理员、不覆盖生产资料、不调用付费生成。
