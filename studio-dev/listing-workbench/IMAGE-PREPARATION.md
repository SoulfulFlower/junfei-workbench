# 文案后图片准备与预算边界

## 本版范围

原 selection_to_copy 任务仍止于文案。图片准备清单仅是已保存元数据的只读报告，不改变任务状态、cursor、审核、预算、执行范围或已有回执，不生成、下载、上传图片，不运行模型或 ERP。

任务中心“查看图片准备清单（不作图）”提供预览与本地 JSON 下载。接口为 GET /api/agent/image-preparation?id=<任务ID>&revision=<工作台版本>。只允许当前账户的原选品到文案 blocked 草稿任务；已有图片阶段、交付、ERP 记录不走此入口。未保存编辑不在清单中，应先保存并更新资料重检。

## 清单如何形成

- 校验原候选产品、ASIN、站点、店铺身份与当前工作台快照和版本。
- 选品货源、竞品、文案三个检查均通过且无未知付费尝试，才可能显示元数据准备通过。
- 只使用实际采集的 Amazon 子体和显式保存的子 SKU，不根据颜色×尺码生成虚构组合，也不自动剔除无货源子体。
- 母版颜色先完成整套；其他颜色在母版审核后制作各自完整套图。计划图片数是颜色数×gallery_count，并非已生成数。
- 当前审核和导出仍固定7图；配置改为其他张数会明确阻断，不虚称兼容。
- 来源图只记录原索引、定位符哈希和本地/远程类别。不打开像素，不下载远程素材，不替代真实颜色、版权或质量审核。
- 读取现有图片、套图和提交回执。文件损坏或表结构缺失不能当成“无历史”；进行中或未知结果须先核对，不能重发。
- 双读任务、工作台、配置和历史，发现检查期间变更即拒绝这次预览。

报告中的 productionReady、imagesReady、executionAllowed、paidCallsAllowed、humanReviewed、stockVerified 始终为 false。readyForManualPreparation 只表示本次元数据条件齐全，不是生成授权或已完成图片。

## 预算审计结论

当前不能实现可信的全流程人民币硬封顶，因此没有把任务 budgetCny 改称费用上限：

1. 文案可能包括主生成、修复、翻译等多次文本请求；研究 JSON 请求缺少统一输出上限和完整 usage 记录。
2. 视觉读图、分镜和审核经过不同模型出口，不进入图片张数的金额预留。
3. 网页各账号与 CLI 账本分离；共享供应商密钥的其他客户端也不受本地锁管理。
4. 报价、汇率、订阅配额与真实人民币账单不能直接等同。供应商接受后超时仍可能收费，不能因客户端失败释放预留。
5. 本地 SQLite 原子预留最多构成已接入路径的准入控制。真实硬封顶还需供应商强制额度/隔离余额以及并发、透支和延迟账单行为的验证。

本轮修复 CLI 图片预算的一个有限缺口：历史未结 reserved 继续占当天额度；状态单列 carryover_reserved_rmb；已结历史费用不重复计入当日；同任务已出现 over_budget 时不再 reserve/claim。这些改变只覆盖 CLI 本地账本，不自动同步网页或限制供应商账单。结算仍按原费用归属日记录。

## 验证边界

测试使用临时账号数据库、合成子体和离线替身；不得以合成夹具代替真实选品、库存或图片事实。未运行付费服务、真实图片制作、ERP、生产部署或另一台实体电脑冷启动。真实端到端验收仍待完成。
