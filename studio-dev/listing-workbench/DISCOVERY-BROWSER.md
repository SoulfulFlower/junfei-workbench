# 本地浏览器 Seller 与卖家列表只读采集

## 本轮范围
对已保存搜索观察中的 ASIN，可从当前账号明确绑定的 EGO 商品页读取实际 Sold by 标签、可见卖家链接和 Seller ID；对已保存 Seller 可读取当前绑定的卖家商品列表，再从保存的商品标题准备下一轮词。标题搜索、自动导航/翻页、同款视觉判断、排名、1688 货源和利润核实仍未自动打通。
结果首先是预览。只有明确点击保存，才写入独立循环证据链；不会自动写产品库、生成文案图片、花费费用或刊登。成功采集仍为 unverified_observation，未获得独立核实的“真实卖家”或“合格产品”结论。

## 独立发现路由与本地账号绑定
只读取当前实例配置的顶层 `discovery_browser`，与 ERP 使用的 `browser` 分开。`engine` 必须为 `ego-lite`，`cli` 必须是这台电脑实际已安装 CLI 的绝对文件路径。`account_bindings` 按本地登录会话的数字账号 ID（JSON 字符串键）选择，只使用当前账号条目，不接受请求或导入 JSON 指定账号。

新便携包默认值为：
```json
"discovery_browser": {
  "engine": "ego-lite",
  "cli": "",
  "account_bindings": {}
}
```
没有 CLI 或当前账号绑定时停止。不会使用 PATH 猜测、ERP 的 CLI、`browser.discovery_account_bindings` 或其他旧配置作为回退。打包校验禁止预置任何专用 CLI 和任何账号条目，包括 `enabled=false` 的条目。

完成本机授权和实际空间核对后，账号条目必须包含 `enabled: true`、非负整数 `task_space_id`、非空 `task_space_name` 和 `page_label`。例如以下仅表示结构，17 和 23 都是示例值，不是可复制使用的真实账号或空间：
```json
"account_bindings": {
  "17": {
    "enabled": true,
    "task_space_id": 23,
    "task_space_name": "本机独立选品空间",
    "page_label": "当前待核实商品"
  }
}
```
`task_space_id` 不得等于 ERP 的 `browser.task_space_id`。空间 ID、名称、agent 所有权和唯一页面标签均须与 EGO 实际状态一致。采集器不创建、接管、导航、刷新或点击页面，不安装扩展、不读取或迁移 Cookie。用户接管、页面缺失、ASIN/站点不符、验证码或登录拦截时停止，不解决验证码或绕过限制。

### 旧配置迁移
1. 确认当前实例和登录账号的真实数字 ID，以及已授权的独立发现空间和页面。不能以旧电脑账号 ID 推断新电脑账号。
2. 在同一实例配置新增顶层 `discovery_browser`，填写本机已安装 CLI 和该账号的独立绑定。不要为了发现功能修改或复制 ERP 的空间路由，不要把 ERP 空间用作发现空间。
3. 旧 `browser.discovery_account_bindings` 不再生效。由该实例管理员核对后清理旧字段；程序不会自动迁移或复制登录状态。本机已有明确绑定不代表便携包携带该绑定。
4. 先查看只读预览和回执，再明确保存证据。缺少配置或被阻止时先核对原因，不启用回退，也不清空未知执行记录。

### 采集期间配置变化
范围指纹仅包含发现引擎、当前会话账号及其有效路由（CLI 解析路径、启用状态、空间 ID/名称、页面标签）。无关的 ERP 字段、其他经营参数和其他账号绑定变化不会使当前观察失效。当前账号路由变化或新出现的 ERP 空间冲突会在执行前后重新校验并阻止保存结果。页面身份、所有权和父搜索版本仍有独立校验，不能用“配置未变”跳过。

## 使用入口
在“选品研究 → 本地循环发现证据链”打开含搜索事件的报告，选择该搜索中的候选 ASIN，再点击“只读采集当前已绑定页面”。
先在授权的专用浏览器页面打开目标商品。采集器不会替用户打开或切换页面。页面身份、空间所有权在读取前后都会检查；中途变化会丢弃可保存结果。
预览包含精确父搜索、ASIN、站点、时间、清理后的卖家链接、可见标签、提取器 SHA256 和绑定摘要。品牌链接、发货方、隐藏链接、店铺卡片和不支持的版式不用于构造 Sold by 证据。
仅保存公开卖家/商品身份所需的 URL 部分，去除其他查询参数和片段；不保存整页、买家姓名、账户信息或任意运行时日志。

## 失败和重试
账号独立 discovery_browser.sqlite3 保存每次意图及结果，不修改 workspace 或任务队列。
同一 captureId、相同输入只读取已有回执；不同输入复用编号会拒绝。并发相同请求最多启动一次。
capture_started / execution_unknown 会阻止该账号继续采集，不能盲目重试。界面“读取本次回执”只读取记录，不重新执行。迟到输出不会自动变成成功；本轮没有提供解除未知状态或自动恢复入口，需先核对原运行是否结束再实施后续恢复功能。
configuration_blocked 表示本地绑定未就绪；blocked 仅说明此次未取得可保存观察，不代表该商品没有卖家。
保存仍要求循环版本匹配。新版本/账号/页面切换后旧响应不显示，不自动提高版本重试。

## 可选真实 HTTP 验收工具
`packaging/verify_live_discovery.py` 只收录在对应源码压缩包，不是便携运行时或启动步骤，不会因启动工作台、离线测试或打包而自动运行。

显式运行需要 Python 源码环境、项目路径、真实采集的 keyword → search 两条源观察、搜索结果中的目标 ASIN、新建的项目 `outputs` 下输出目录，以及 `--read-bound-browser` 选项。必须事先确认独立 EGO 页面已在允许读取的目标商品上。该工具会创建隔离账号与临时 SQLite，只读取配置中会话账号 1 的专属发现绑定；这里的账号 1 是隔离验证实例的账号，不会登录或写入正式账号账本。

验收目标是一次真实浏览器只读采集、通过已认证本地 HTTP 取得回执、明确写入隔离证据链并验证重复请求不重放。其他失败检查可包含明确标注的模拟超时，不得说成真实浏览器超时。工具不导航、不接管、不调用付费服务、不操作 ERP、不上传发布，不得以失败为由重复未知操作。查看生成报告的 `success`、真实派发次数和错误后，才能判断本次是否通过；存在工具或测试通过不代表真实 HTTP 验收已经执行。

即使验收通过，观察仍为 `unverified_observation`，`qualificationEvaluated=false`，合格数和产品入库数仍为 0。不会因此取得选品、货源、利润、图片或刊登授权。

## 卖家列表与下一轮标题词（2026-11-06）
新增两个明确动作，沿用同一账号和独立发现空间，不调用 ERP：
- 对已记录 Seller 的当前绑定页面做一次只读列表采集。只支持同站点 Amazon /s?me=该 Seller ID 的实际结果列表；品牌 /stores/、冲突身份参数、错误站点、登录/验证码/访问阻挡或不支持的结构会停止。
- 从已保存 store 事件的商品中选择 ASIN，输入标题开头词，再预览并明确保存 keyword。前缀按已有大小写、标点、NFKC 规范化规则校验，可去掉已明确记录的品牌前缀；不能把后段或扩展词当原词。

列表采集只读取 .s-main-slot 的直接商品结果卡，使用实际 h2 商品标题及对应 ASIN 链接，排除已识别的广告和嵌套推荐。仅记录当前加载的最多 50 条；不是全店扫描，也不证明该商品当前购买框仍由原 Seller 销售。CSS 可见不等于每个结果都在当前视口；不会滚动、翻页或加载更多。此结构已依据一个 US 实页编写，其他版式仍可能阻断。

店铺采集和商品 Seller 采集共享账号未知状态与并发保护。任何类型存在 capture_started / execution_unknown 时，不能换另一类型或换 captureId 重读。同一编号跨类型重用拒绝。缺少可保存产品会留下阻断回执，不把加载中或空白状态写成“卖家没有商品”。

新词预览完全只读。词源标题与 ASIN 来自精确父 store 事件，observedAt 保留原列表观察时间，不伪造新的商品页读取时间。相同准备生成稳定事件 ID，明确保存仍校验当前循环版本，重复保存不会新增；不会执行下一轮搜索。

接口：
- POST /api/discovery/capture-store：captureId、cycleId、expectedRevision、parentId、sellerId。
- POST /api/discovery/prepare-keyword：cycleId、expectedRevision、parentId、asin、phrase。
两者均要求本地登录会话、同源和不超过 4 KiB 请求，不接受指定 owner。捕获与新词预览均返回 preparedBatch；必须另行明确 ingest 才入独立发现账本。
