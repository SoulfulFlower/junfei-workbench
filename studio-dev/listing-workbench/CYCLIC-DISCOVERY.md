# 本地循环发现证据链

## 当前范围

本版只部署目标为本地单机独立工作台。每台电脑和每个账号保留自己的发现账本，不迁移、合并或修改旧产品库、旧任务或云服务器。

新增的是循环发现的可追踪核心与结构化采集接入口，不是已经连通的无人值守选品。界面位于“选品调研 → 本地循环发现证据链”，可下载空白格式说明、选择已采集 JSON、明确点击保存、查看每条来源关系及下载完整报告。选择文件本身不会保存。

采集插件和无人值守浏览器循环到该账本的实时接入尚未实现。初版核心验收只使用合成数据；后续已增加当前 EGO 商品页的 Seller 只读预览和明确保存入口，并完成一个 US 商品页提取器实测。2026-11-06 已完成一次真实本地 HTTP 采集到隔离账本验收，仍没有真实新增入围产品。现有旧观察缺少商品页实际 Seller 链接时，不能自动补造或导入成完整链。

## 证据顺序

1. keyword：来源商品ASIN、站点、标题原文、标题开头短语和商品链接。可只去掉明确记录的品牌前缀，不能把标题后段或凭空扩展词冒充原始词。
2. search：必须引用上一步关键词，保存相同查询的同站点Amazon搜索链接、时间和可见商品。EXACT/CLOSE/RELATED/REJECT只记为提供者的待核验分类，标题相似不能自动变同款。
3. seller：必须引用前一步实际搜索结果中的ASIN，保留该商品URL、Sold by可见标签、卖家名、实际卖家链接和Seller ID。品牌单独记录，不能以品牌旗舰店、品牌名称或第三方推测代替卖家链接。
4. store：必须引用该Seller事件，实际店铺商品列表URL的me必须与Seller ID一致。店铺卡片只产生store_listed_product关系，不反推其购买框卖家。不可访问需保留原因，不能编造商品。
5. 下一轮keyword：必须来自前一步店铺真实记录中的ASIN与标题，保留具体父事件，之后回到search。

时间须含时区，子事件不能早于父事件，明显未来时间拒绝。官方域名、站点、ASIN、seller/me/k参数均验证；凭据URL、伪造域名、重复冲突参数、错误前驱或循环父引用拒绝。

## 保存与报告

- 发现账本独立按账号保存。owner来自登录会话，不接受JSON指定账号。
- 一批最多100条事件，一个循环最多5000条。events[].id是稳定事件ID；相同ID相同规范化内容幂等，相同ID不同内容整批拒绝。
- expectedRevision必须匹配当前循环版本。写事务为BEGIN IMMEDIATE；并发冲突不自动覆盖或重试。全重复请求不会提高版本。
- 商品按站点+ASIN、卖家按站点+Seller ID、词按站点+规范词去重，同时保留所有具体来源边。
- search和store逐个商品保留未处理分支，不会因处理一个商品而隐藏其余待办。已搜过的重复词、空结果和访问失败分别标记，不自动执行下一步。
- 完整导出包含清洗后的events、parentId、来源URL、时间、round、节点、边和queue，空搜索原证据也保留。
- qualificationEvaluated=false；核验通过和入库数均为0。发现记录数量绝不作为选品通过、出单、完成货源核验或实际产品入库数量。
- 所有观察均是unverified_observation。结构校验不认证JSON是否真的来自浏览器，不验证照片同款、数值销售排名、库存、知识产权、运费或利润。

## 本地接口

- GET /api/discovery/template?market=US
- GET /api/discovery/history
- GET /api/discovery/report?id=<cycleId>
- POST /api/discovery/ingest，JSON为cycleId、expectedRevision、events。
- POST /api/discovery/capture-seller 与 /capture-store：当前绑定页面只读预览，不能自动导航。
- POST /api/discovery/prepare-keyword：从已记录 store 的精确商品标题准备前缀，只读，需另行明确保存。

写入需要本地会话和同源请求。当前未为浏览器扩展开通该写入入口；不应通过复制Cookie或放宽Origin绕过。

## 发现路由与迁移
当前浏览器读取仅使用顶层 `discovery_browser`，结构为 `engine: "ego-lite"`、本机已安装 CLI 绝对路径 `cli`、按登录会话数字账号 ID 索引的 `account_bindings`。每个启用条目要求非负整数空间 ID、非空空间名和页面标签；空间不能与 ERP 的 `browser.task_space_id` 相同。旧 `browser.discovery_account_bindings` 不再读取，也不会从 ERP 路由回退。完整配置及迁移步骤见 DISCOVERY-BROWSER.md。

便携默认配置中的 CLI 为空、绑定为空。各电脑分别核对本地账号、空间和授权，不复制旧电脑配置或 Cookie。当前账号的有效发现路由在读取前后核对；无关 ERP/经营配置变更不会误阻止观察，但当前路由变化或新增空间冲突会停止。

对应源码包含显式选用的 `packaging/verify_live_discovery.py`，仅用于真实源观察 → 本地 HTTP → 隔离账本验证，不在启动时运行，也不写正式业务账本。无论离线测试、单页采集或隔离验收是否通过，发现记录仍待核验，不增加合格数或产品入库数，不代表自动循环、经营核实或发布完成。


## 卖家列表标题接续
新增两个明确动作，沿用同一账号和独立发现空间，不调用 ERP：
- 对已记录 Seller 的当前绑定页面做一次只读列表采集。只支持同站点 Amazon /s?me=该 Seller ID 的实际结果列表；品牌 /stores/、冲突身份参数、错误站点、登录/验证码/访问阻挡或不支持的结构会停止。
- 从已保存 store 事件的商品中选择 ASIN，输入标题开头词，再预览并明确保存 keyword。前缀按已有大小写、标点、NFKC 规范化规则校验，可去掉已明确记录的品牌前缀；不能把后段或扩展词当原词。

列表采集只读取 .s-main-slot 的直接商品结果卡，使用实际 h2 商品标题及对应 ASIN 链接，排除已识别的广告和嵌套推荐。仅记录当前加载的最多 50 条；不是全店扫描，也不证明该商品当前购买框仍由原 Seller 销售。CSS 可见不等于每个结果都在当前视口；不会滚动、翻页或加载更多。此结构已依据一个 US 实页编写，其他版式仍可能阻断。

店铺采集和商品 Seller 采集共享账号未知状态与并发保护。任何类型存在 capture_started / execution_unknown 时，不能换另一类型或换 captureId 重读。同一编号跨类型重用拒绝。缺少可保存产品会留下阻断回执，不把加载中或空白状态写成“卖家没有商品”。

新词预览完全只读。词源标题与 ASIN 来自精确父 store 事件，observedAt 保留原列表观察时间，不伪造新的商品页读取时间。相同准备生成稳定事件 ID，明确保存仍校验当前循环版本，重复保存不会新增；不会执行下一轮搜索。

接口：
- POST /api/discovery/capture-store：captureId、cycleId、expectedRevision、parentId、sellerId。
- POST /api/discovery/prepare-keyword：cycleId、expectedRevision、parentId、asin、phrase。
两者均要求本地登录会话、同源和不超过 4 KiB 请求，不接受指定 owner。捕获与新词预览均返回 preparedBatch；必须另行明确 ingest 才入独立发现账本。
