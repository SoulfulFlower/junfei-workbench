# Amazon AI Product Studio 全站信息架构与 Design System

## 导航与页面路由

侧栏固定提供工作台、产品档案、Listing、图片工厂、质检、ERP 交接、Skill 和任务。设置及帮助在侧栏底部。各模块接通后开放入口。顶部保留面包屑、当前站点/产品和账号。产品详情下的 Listing、图片、质检与 ERP 链接去各模块的同一个产品上下文。选品由循环选品技能执行，工作台保留已记录的发现指标与产品档案中的来源证据。

| 目标路由 | 页面 | 首屏与主要交互 |
| --- | --- | --- |
| `/` | 工作台首页 | 8 个运营指标、最近任务表和快捷入口。今日以业务时区为准，缺口以“未接通”或“暂无证据”显示。 |
| `/products`、`/products/:id/:section` | 产品档案 | 可筛选的产品表与状态列；详情用资料、竞品、关键词、Listing、图片、质检、ERP、历史标签。 |
| `/listing`、`/products/:id/listing` | Listing 工作台 | 左侧事实和 MCP 证据，右侧 Title、Bullet Points、Description、Search Terms、Attributes、Keywords；页首批量/生成，字段内锁定、生成、优化、保存和版本。 |
| `/images`、`/products/:id/images` | API 图片工厂 | 左侧参考图，中间图位与大图，右侧按需打开 Prompt、API 模型与任务参数；下方版本记录。保留刚验收的按图位浏览和 ZIP。 |
| `/quality`、`/products/:id/quality` | 质检中心 | 按规则和严重度筛选队列，详情分文案、关键词、图片、资料和人工审核。 |
| `/erp`、`/products/:id/erp` | ERP 交接 | 预检清单、版本和店铺核对、明确确认、提交与回读证据；异常时先查同一操作。 |
| `/skills`、`/skills/:id` | Skill 中心 | 固定九项技能的目录和版本；详情展示输入输出、执行条件与实际执行记录。 |
| `/tasks`、`/tasks/:id` | 自动化任务 | 带真实计数的任务表，详情是阶段时间线、输入输出、失败原因和恢复动作。 |
| `/settings`、`/help` | 设置与帮助 | 集成、账号、权限、备份和操作说明。 |

路由过渡以集中登记的页面路径为准。已有 `?product=…&step=…` 深链继续解析。产品、站点及可分享的过滤条件放 URL，未保存表单保存在页面状态。浏览器后退/前进恢复页面；未知路由给出可返回的 404。账号门禁在服务端，任何请求都按产品归属验证。Windows 便携和开发实例使用同一套路由。

## 设计系统

设计取向为安静、明确、实用，像电商资料台与摄影选片台。品牌深蓝用于当前导航、焦点与主操作。内容丰富度来自真实产品、指标和证据，页面不再用装饰性大卡片填空。

| 规范 | 值与用法 |
| --- | --- |
| 品牌主色 | `#234D7C`，悬停 `#193B63`。白字主操作。辅助信息色 `#3D5974`，用于来源链接及次要强调。 |
| 中性色 | 背景 `#F4F6F9`，工作面 `#FFFFFF`，轻背景 `#EDF2F7`，边线 `#D8E0E9`。文字 `#17263A`、`#41536A`、`#5D6D80` 三层。 |
| 状态色 | 通过 `#216746`、警告 `#815319`、不通过 `#992F37`、处理中 `#234D7C`、未知 `#5D6D80`。状态标签必须带文字；“已保存草稿”“已回读”“已发布”分别显示。 |
| 字体与字号 | `Segoe UI, Microsoft YaHei UI, system-ui, sans-serif`。正文 14/22，说明 12/18，小标题 16/24，区标题 20/28，页标题 28/36。常用 400/600，数字用等宽数字。 |
| 间距与尺寸 | 4px 基准，4、8、12、16、24、32。常规工作区边距 24，紧凑视图 16。桌面侧栏 224、顶栏 56，输入和主要按钮 36–40px。 |
| 圆角与阴影 | 控件 6px、面板 8px、弹窗 12px。面板靠边线区分，浮层才使用 `0 8px 28px #17263A26`。 |
| 按钮 | 主、次、文本和危险四种。单区只强调一个主操作。加载禁重复提交，失败可恢复，危险动作在确认前说明对象和影响。 |
| 表格 | 40–48px 数据行，列标题可辨别，数值右对齐。数据来自已验证的查询。窄屏优先保留身份和阶段，其他字段在详情中可见。 |
| 输入 | 永久标签、示例提示、字段级校验、明确禁用和焦点。必填与可选有文字说明，错误就地显示。 |
| 弹窗与详情 | 使用可访问对话框，保留关闭按钮、Esc 与焦点返回。长流程用页面或侧栏详情，危险动作才用确认弹窗。 |
| 导航 | 16px、1.5px 描边图标，短标签，活动态同时有文字/底色。移动端折叠主导航，三个栏位按列表→详情顺序重排。 |
| 反馈 | 加载、空、错误、保存成功由真实请求/事件驱动。按钮不可用时说明条件。键盘焦点可见，尊重减少动态效果设置。 |

实现采用集中令牌、共享按钮/表格/表单/对话框/状态组件。HTML 与 React 在迁移中读同一套 CSS 令牌与组件契约。新页面禁止新建同义配色和状态模型。旧页面随验收逐页迁移，既有工作流程在迁移前仍可使用。

## 业务与数据合同

- 产品身份按账号、产品内部 ID、站点关联。选品、文案、图片、质检、ERP 和任务各保留来源 ID、事件时间及内容版本，阶段汇总可反查证据。数据库迁移采用新增表/字段、备份、可重放回填和隔离回滚演练。
- 选品记录每个竞品的子 ASIN、经核实的 Parent ASIN、标题、链接、关键词来源、时间、卖家及店铺。按已核实 Parent ASIN 去重，3–5 个才可通过。Parent ASIN 未知不算不同父体。关键词→同款→竞品→卖家→店铺→店铺商品→新关键词的每步保留证据。
- Listing 生成以资料和真实 MCP 数据的版本为输入。记录采集时间、市场、工具、指标、关联词及请求使用的证据。MCP 失效或竞品不足时显示待补或错误，人工编辑和既有版本仍可读取。锁定字段用服务端规则保护。
- 图片工厂新提交只允许 API，API Base URL、反向代理、密钥、模型、参数、超时与重试可配置。密钥在服务端配置。外部提交结果未知时查回执，不能盲重发。按产品/站点/颜色/图位/版本记录生成和排序。删除先查交付引用，已用素材留历史。
- 质检按输入版本记录规则、结果、证据、复核人和时间。技术检查、模型检查和人工审核分别计数。参考尺码供应商未确认时保留警告与交付门禁。
- ERP 先展示已核对的输入版本和店铺，明确人工确认后使用现有受控浏览器桥接。以账号/站点/产品/版本记录意图，已有 SKU 先查，超时先读回，单独标注产品库已创建、草稿已保存与已验证。发布权限不由交接动作推导。
- 任务共用事件语义。状态包含等待、处理中、待人工、阻塞、暂停、失败、已完成、提交结果未知。真实任务计数按统一身份去重。断点保存阶段输入、输出、外部任务 ID、尝试号和失败原因。可恢复、不可重试与需先对账分别处理。
- 工作台指标从当前账号事实聚合。产品总数来自产品档案。今日选品从有时间的发现证据按站点/ASIN 去重，显示时区。阶段指标各用文案任务、图像任务、质检或 ERP 回执；证据不齐显示“未接通”，不用 0 填补。最近任务按真实时间倒序，标注来源。

## 分阶段验收顺序

1. 完成现状审计、路由和全站设计系统。确定保留业务、数据来源和缺口。
2. 首页与导航。核对真实汇总、空账号、加载和错误、深链/返回、桌面和窄屏。
3. 产品档案。核对循环选品技能证据的建档关联、产品表、详情、账号隔离、全历史及迁移回读。
4. Listing。核对至少 3 个不同竞品父体、MCP 数据真实进入模型请求，以及锁定、改写、版本、批量和阻塞条件。
5. 图片工厂。核对 API 参数、整套与单图、历史、排序、下载、超时恢复。
6. 质检。核对通过、警告、失败、人工复核及版本失效。
7. ERP。核对插件能力、受控交接、人工确认、图序和读回、断点去重。
8. 任务中心与 Skill。核对真实进度、暂停/继续/重试、跨链路状态和 Windows 两机验收。

每个模块通过真实运行截图、浏览器交互、数据库与 API 对照、空数据/失败和视口检查后，再进入下一模块。发布包验收独立记录对应源码、备份恢复及第二台 Windows 实机。
